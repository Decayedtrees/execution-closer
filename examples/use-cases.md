# Anonymized usage observations

These four cases are derived from real Agent response excerpts, not independently reproduced project runs. Names, paths, repositories, environments, identifiers, measurements, and scientific findings are omitted. The original screenshots remain private. Reported progress is evidence about the responses, not proof that this skill caused the outcome.

| Case | Reported progress | Design implication |
| --- | --- | --- |
| Remote scientific data | Prepared collection, packaging, and safe extraction tools. The actual data had not arrived, so the core analysis remained pending. | Useful preparation counts as progress, but must be labeled. A data dependency can be a real blocker; the excerpt does not establish whether manual transfer was unavoidable. |
| Scientific computation | Ran an existing analysis with additional inputs and reported an independent check. Scientific interpretation still required further validation. | A verified computation and an unresolved interpretation can coexist. The excerpt called this `Blocked` while explicitly saying computation was not blocked. Separate attention from inability to continue. |
| Game development | Completed a scoped gameplay adjustment, preserved existing progress, reported focused and regression checks, and uploaded the branch. Creating a change request failed through one integration. | Keep concrete execution and regression. Check other available authorized routes before handoff; the excerpt does not prove another route existed. |
| Software audit | Produced the requested review package, reported static and coverage checks, and excluded credential files. Device validation had not been performed. | A document can be the deliverable. Report static verification honestly without implying device-level validation. |

A separate old-project excerpt offered a small experiment to assess whether a game idea was worth continuing, and explicitly reported no file changes. Without the original request, this is not evidence of an execution failure. It motivates a routing boundary: requests for advice about continuing a project should not automatically start implementation.

The excerpts do not establish unnecessary planning-document creation, scope creep, poor task selection, or missing intermediate checks. The candidate's concise scope, dependency, and verification boundaries address those risks without claiming they occurred.
